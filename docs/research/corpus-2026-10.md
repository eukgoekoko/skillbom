# License landscape of public agent skills — corpus study, October 2026

We scanned 1,211 public GitHub repositories that contain agent skills: 62,704 distinct skills and 3,578 plugins. The scan used `skillbom` 0.1 on 2026-10-22/23. The question was simple: when a company installs a public skill, can it tell what license that skill is under?

## Headline findings

1. **Licenses live at the repo root; skills travel alone.** 92.5% of the repos have a root LICENSE, but only 22.5% attach a license to *every* skill itself, in the SKILL.md frontmatter or in a LICENSE file in the skill's folder. 80.5% of all skills are licensed *only* through their repo's root LICENSE. Skills get installed by copying a single folder into `~/.claude/skills/`, and that copy carries no license.
2. **The official marketplace is no better.** Only 15.9% of the 195 official-marketplace repos with skills license every skill individually, and 9.7% contain at least one skill with no license at all, compared with 6.9% across the whole corpus.
3. **Restrictive licenses are rare but real.** Repos with at least one skill under each type of restriction:

   | restriction | share of repos |
   |---|---|
   | copyleft | 4.3% |
   | proprietary | 2.1% |
   | non-commercial (CC-BY-NC*, PolyForm Noncommercial, BUSL) | 1.8% |
   | custom, needing a human to read it | 1.2% (3.6% in the official marketplace) |
   | source-available with service restrictions (Elastic, FSL, Commons Clause) | 0.8% |

   At skill level: 681 skills don't permit commercial use, and 1,326 carry custom terms.
4. **Proprietary skills are being redistributed.** 12 repos outside Anthropic ship copies of Anthropic's document skills (docx, pdf, pptx, xlsx), 43 copies in total. Each copy still carries its "© Anthropic, PBC. All rights reserved" LICENSE.txt, which ties use to the user's agreement with Anthropic. Some of these repos are popular "awesome" collections, and at least one has no license of its own. Whether this is permitted is a legal question we don't answer. A company that installs from these collections inherits that question without knowing it.
5. **Nobody declares licenses in machine-readable form yet.** 15.7% of skills use the SKILL.md `license:` key (27.6% in the official marketplace), and about 2% of those values are free text rather than SPDX ("Proprietary. LICENSE.txt has complete terms", "SEE LICENSE IN LICENSE", "BSD-3-Clause license"). No skill uses a dedicated license file, as expected, since the format is ours and new.

Taken together: for about four out of five public skills, an installed copy says nothing about its license. That is the gap a Skill BOM and a skill-level license file are meant to close.

## Corpus and method

| | |
|---|---|
| Candidate repos | 1,511: the external sources of the official Claude Code marketplace (227) plus GitHub repository search for skill/plugin topics, sorted by stars (no forks, no archived repos) |
| Fetched | 1,495 (16 failed: timeouts, unreachable or deleted repos) |
| Containing skills | 1,211; median 5 skills per repo |
| Distinct skills / plugins | 62,704 / 3,578 (deduplicated by content hash; 157 skills appear verbatim in several repos) |

Scripts are in `scripts/corpus/`: `collect.py` builds the list, `fetch.py` fetches only the skill-relevant files, and `analyze.py` runs the scanner and aggregates. Raw per-repo BOMs land in `.corpus/`, which is not committed.

- Each repo is scanned as a whole with `--root`. A skill inherits the nearest ancestor LICENSE up to the repo root, which matches how a careful human would read the repo.
- Detection is heuristic: SPDX expressions in manifests and frontmatter, free-text license names, and key-phrase matching of license texts (see `docs/skill-bom.md`). A license text that matches no known license counts as *custom*, not *none*.
- **Per-repo numbers are the headline.** Per-skill numbers are dominated by a few very large repos; one repo alone contributes about 23,000 skills under "Apache-2.0 OR MIT".

### Limitations

- **Sample:** this is a topic-and-marketplace sample, not a census. GitHub code search for `SKILL.md`, which needs a token, would reach repos without topics. The sample leans toward popular repos.
- **Snapshot:** one commit per repo (default branch HEAD), not the commit the marketplace pins.
- **Accuracy:** a spot check of 18 random detections found the expected source and expression each time. A proper precision/recall measurement against hand-labeled skills hasn't been done.
- **Content hashes:** 198 repos were fully cloned and the rest fetched with a filter (files over 1 MB and non-skill files skipped), so copy detection across those two groups undercounts.
- **Legal status:** "non-commercial", "proprietary" and "custom" are classifications of the license text, not legal conclusions.

## Detector improvements this study produced

The corpus doubled as a test set. Fixes made to the scanner while running it:

- **Source-available licenses** are now recognized, both as texts and as table entries: PolyForm (Noncommercial, Small Business, Shield, Internal Use), BUSL-1.1, Elastic-2.0, SSPL-1.0, FSL-1.1 and Commons Clause (reported together with its base license). Before this, PolyForm Noncommercial went unrecognized.
- **Free-text names** in `license:` fields are now parsed ("GPLv3 license", "MIT + Commons Clause", Creative Commons URLs, npm `UNLICENSED`).
- **Pointer texts and translated licenses** are matched by their title line ("MIT License – see repository root LICENSE").
- **Unknown license texts** are reported as `LicenseRef-custom` with a `license-review` finding, instead of as "no license".
- **Own evidence beats inherited evidence** (found earlier on a real install). The study confirms it matters: many repos have a permissive root LICENSE but individual proprietary or non-commercial skills.
